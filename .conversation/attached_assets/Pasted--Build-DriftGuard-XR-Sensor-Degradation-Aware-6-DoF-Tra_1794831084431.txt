# Build DriftGuard XR — Sensor-Degradation-Aware 6-DoF Trajectory Estimation

You are building a serious computer vision and robotics research prototype called **DriftGuard XR**.

This is NOT a landing page, generic analytics dashboard, or frontend-only simulation.

The project addresses:

**Trajectory estimation under sensor degradation for Extended Reality (XR).**

The objective is to develop and demonstrate a robust visual-inertial trajectory estimation system that maintains reliable 6-DoF pose estimates when camera and IMU measurements become unreliable.

The central technical contribution is an adaptive visual-inertial estimator incorporating geometric observability analysis and Geometric Observability Index (GOI)-inspired feature influence diagnostics.

Build an actual functioning application with a reproducible simulation, numerical estimation algorithms, comparison baselines, evaluation metrics, and an interactive 3D visualization.

### Adaptive sensor reliability

Compute a visual quality estimate using:
- Feature count
- Feature spatial distribution
- RANSAC inlier ratio
- Reprojection RMSE
- Motion blur indicator
- Feature dropout
- Parallax
- Geometric conditioning

Compute inertial quality using:
- Measured noise
- Saturation
- Missing packets
- Innovation residual
- Bias estimates

Adapt visual measurement covariance and inertial process covariance based on sensor health.

When visual tracking becomes unreliable:
- Downweight or temporarily reject unreliable visual updates.
- Continue inertial propagation.
- Increase uncertainty appropriately.
- Avoid pretending the pose remains accurate.

When visual observations recover:
- Validate them against the predicted state.
- Apply robust visual correction.
- Track recovery time.

Compare this estimator against the fixed-weight baseline using identical sensor observations.

## 5. GOI and geometric observability module

Create a separate `goi` package.

Implement per-feature influence computation for SE(3) pose estimation.

For each feature:
- Calculate reprojection residual.
- Calculate its pose Jacobian.
- Calculate the weighted Gauss-Newton curvature matrix.
- Perform eigendecomposition.
- Identify the observable subspace.
- Calculate the feature's influence in that observable subspace.
- Calculate its GOI value.

Use a clearly documented SE(3) metric to handle translation and rotation units.

Recenter coordinates around the current camera pose when computing geometry-sensitive diagnostics.

Display:
- Individual feature GOI
- Feature residual
- Feature robust weight
- Curvature eigenvalues
- Condition number
- Weakest observable direction
- Translation versus rotation observability
- GOI distribution over time

IMPORTANT:
GOI must NOT be implemented as a simplistic outlier score.

Do not reject observations merely because they have high raw GOI.

Use normalized residual-based robust estimation for outlier handling, while GOI is used for influence attribution and geometric sensitivity diagnostics.

### GOI-informed keyframe selection

Implement a keyframe utility based on:
- Incremental information gain
- Weak-direction observability improvement
- Feature coverage
- Parallax
- Geometric conditioning

Compare against a simple fixed-interval keyframe policy.

Expose the keyframe decisions and their numerical reasoning.
